# draft-from-examples

Input: the folder of examples and the topic of the new document, as the user gave them.

1. **Read the examples.** Read every finished document in the folder, or the five most recent if there are more than ten. Skip drafts and templates unless the user points at them.

2. **Write down the pattern before drafting.** Note the sections and their order, the typical length of each, headings, tables or lists, and fixed boilerplate. For voice, note person, tense, formality, sentence length, and phrases the examples repeat. Also note what changes from one example to the next, because that is the part the new topic fills.

3. **Gather the facts for the new topic.** Use the sources the user named, the repo and earlier documents. A fact you cannot find is written as `[TODO: what is needed]` in place, never guessed, because a plausible invented fact in a finished-looking draft is the hardest error to catch.

4. **Draft it.** Save it in the same folder, named the way the examples are named. Reuse their structure and voice. Change only the parts that vary with the topic.

5. **Report.** Give the file path, which examples it follows, and each `[TODO]` left in it.
